No.	Component	Description / Purpose
1	Product Service	Responsible for managing all product-related information such as product name, price, category, description, images, and stock details. It provides APIs to add, retrieve, update, and delete products.
2	Cart Service	Manages the shopping cart for users. It handles adding products to the cart, updating product quantities, removing products, calculating item totals, and maintaining the overall cart amount.
3	Order Service	Responsible for managing customer orders. It creates orders from cart information, maintains order items, total amount, payment method, order status, and order date, and provides APIs for retrieving order details.
4	API Gateway	Acts as the single entry point for the Angular application and external clients. It routes requests to the appropriate microservice and handles cross-cutting concerns such as JWT authentication, CORS, request filtering, and service routing.
5	Eureka Server	Works as the service registry for the microservices. Each service registers itself with Eureka, and the API Gateway uses Eureka to dynamically discover service instances instead of relying on fixed hostnames and ports.
6	Config Server	Provides centralized configuration management for all microservices. Database URLs, server ports, Eureka configuration, and other environment-specific settings are maintained centrally in the configuration repository rather than being duplicated across every service.
7	Auth Service	Handles user authentication and authorization. It validates login credentials, generates JWT tokens, manages user information and roles, and provides the authentication information required to access protected APIs.
8	Resilience4j	Provides resilience and fault-tolerance capabilities for microservices. It can implement Circuit Breaker, Retry, Time Limiter, Bulkhead, and Rate Limiter patterns to prevent failures in one service from cascading to other services.
9	Kafka	Acts as the event/message broker for asynchronous communication between microservices. Services can publish events such as order-created or payment-completed events, while other services can consume those events without requiring direct synchronous communication.
10	Inventory Service	Manages product inventory and stock levels. It updates available stock when products are ordered, checks whether sufficient inventory is available, and helps prevent orders from being processed when products are out of stock.
11	Notification Service	Handles customer notifications generated by business events. It can consume Kafka events and send notifications such as order confirmation, order status updates, delivery updates, email notifications, or SMS notifications.
